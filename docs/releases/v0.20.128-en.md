# v0.20.128 release notes

## Changes from v0.20.127

- Select an available proxy port from `49720–49729`, reuse a compatible service, and return the actual endpoint.
- Discover compatible services from the extension and rediscover after disconnection. Explicit `-Port` / `PORT` values remain pinned to one port.
- Use the discovered endpoint for SMT, PCB backup, and Python helper requests.
- Preserve system error details for binding failures rather than classifying them generically as port conflicts.
- Continue hidden Windows startup through the companion skill. Do not open the legacy startup URL, stop unknown processes, or change system port settings.

## Installation

1. Download the [English/Chinese skill ZIP v2026.11.08](https://github.com/quhuii-lgtm/easyeda-aicommand-skill/releases/download/v2026.11.08/ai-command-engine-skill_v2026.11.08_en-zh.zip) and install the complete `ai-command-engine/` folder in your AI tool's skills directory.
2. Use Node.js >=20.17.0 and run `npm ci --omit=dev` in the skill root.
3. Ask the AI to follow the skill's [connection guide](https://github.com/quhuii-lgtm/easyeda-aicommand-skill/blob/main/ai-command-engine/references/setup.md) and run `scripts/start-proxy.ps1` hidden on Windows.
4. Download the companion `.eext` from the [v0.20.128 plugin release](https://github.com/quhuii-lgtm/easyeda-aicommand/releases/tag/v0.20.128), import and enable it in JLCEDA Pro, and allow external interaction.
5. Use the actual endpoint reported by the launcher to check `/health` and `/connections`. Verify the intended instance and project with a read-only `project.getInfo` call before editing.

## Verification scope

TypeScript checking, a zero-warning build, focused regressions, independent skill installation, port conflict/fallback, compatible service reuse, concurrent cold startup, and HTTP/WebSocket round trips passed. Windows host acceptance on JLCEDA Pro 4.1.93 confirmed hidden proxy startup, discovery and automatic connection at port 49721, 217 registered command names, read-only project/task queries, and the SMT menu opening at the discovered endpoint.

This is limited Windows host acceptance. It does not establish that all 217 commands work, that PCB grouping writes or general drawing passed, that data persists after save/reopen, that whole-board DRC passes, or that the product is ready for manufacturing. Linux host startup and connection have not been tested.
