# v0.20.124 release notes

English | [简体中文](v0.20.124-zh.md)

Date: 2026-10-28. Publication status: see the [GitHub release page](https://github.com/quhuii-lgtm/easyeda-aicommand/releases/tag/v0.20.124). The v0.20.124 marketplace package is provided for the user to upload and has not yet been submitted for this marketplace review. The extension has not been installed for v0.20.124 host acceptance.

## Scope

This release contains three source fixes and a retained correction to the legacy `autoRouteStart` help text. It does not claim new EDA host acceptance. Existing major-feature acceptance remains based on installed v0.20.123 and the applicable earlier records. The currently listed marketplace version is 0.20.51; the previous public GitHub release was v0.20.50.

## Changes

- Task fingerprints preserve array order while continuing to sort object keys. Identical in-flight requests still reuse the running task; argument arrays with different order remain distinct.
- Autoroute terminal states release only the matching job slot. When `Start` finds an older slot, it makes one internal read-only `GET`; a new start proceeds only when the returned job has the same ID and an explicit terminal state. Unknown, running, or identity-uncertain outcomes do not trigger another start write.
- PCB layer-name resolution uses the existing full mapping consistently across selection, routing, display, and locking. Existing `top`/`bottom`, `t`/`b`, numeric values, and numeric strings remain supported. No new layer-count limit or enum preflight was added.
- The legacy `autoRouteStart` help text correction is carried forward; it is not presented as a new SDK or plugin feature.

## Local verification

Ten local regression checks, whole-project `tsc --noEmit --incremental false`, and compilation with the production esbuild configuration passed. These are local checks only. v0.20.124 has not been installed or accepted on an EDA host. Its publication status is shown on the [release page](https://github.com/quhuii-lgtm/easyeda-aicommand/releases/tag/v0.20.124). The marketplace package is provided for the user to upload; this task has not submitted it.

## First installation

Download the extension, complete proxy source, and AI skill separately. The GitHub assets are `easyeda-aicommand-plugin-source_v0.20.124.zip`, `ai-command-engine_v0.20.124_en.eext`, and `ai-command-engine_v0.20.124_zh-CN.eext`. The extension does not install Node.js, the proxy, or the skill. For a first setup, follow the [complete-source installation guide](../QUICKSTART.md). The proxy requires Node.js >=20.17.0 and the full source repository; run `npm ci` and `node bridge/command-proxy.mjs` there. The independent AI skill is [v2026.10.28.1](https://github.com/quhuii-lgtm/easyeda-aicommand-skill/releases/tag/v2026.10.28.1), available as a [complete ZIP](https://github.com/quhuii-lgtm/easyeda-aicommand-skill/releases/download/v2026.10.28.1/ai-command-engine-skill_v2026.10.28.1_en-zh.zip). Install the complete `ai-command-engine/` folder, including `SKILL.md`, alternate `SKILL_ZH.md`, `references/`, `scripts/`, and `VERSION`; reload the AI tool and ask it to read `SKILL.md` and confirm the version. Skill and plugin versions are independent; check relevant functionality and command help rather than matching version numbers.
